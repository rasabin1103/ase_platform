# 0006 — Security headers middleware registered last, CSP exempts `/docs`

## Context

The platform had no HTTP security headers at all (no HSTS, X-Frame-Options, X-Content-Type-Options, or CSP) — an easy, low-risk hardening gap to close.

## Decision

`install_security_headers(app)` (`app/core/security_headers.py`) registers a `@app.middleware("http")` handler and is called **last** in `app/main.py`, after `CORSMiddleware` and after the rate-limiter middleware — meaning it's the **outermost** layer, so every response gets the headers, including CORS preflights and 429s from the rate limiter. Headers applied unconditionally: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, a locked-down `Permissions-Policy`. `Strict-Transport-Security` is added only when the request is actually over HTTPS (checked via `request.url.scheme` or a proxy-forwarded `X-Forwarded-Proto` header, so it works correctly behind a reverse proxy that terminates TLS). `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'` is applied to every path **except** `/docs`, `/redoc`, and `/docs/oauth2-redirect`, which need to load Swagger/ReDoc's own CDN-hosted scripts to render at all.

## Alternatives considered

- **Apply CSP everywhere including `/docs`.** Rejected: breaks the interactive API docs entirely (Swagger UI loads external JS/CSS it can't function without) — traded a small, well-understood exemption for keeping `/docs` usable in production if left enabled.
- **Register the middleware first instead of last.** Rejected: middleware registered first ends up as an inner layer in Starlette's model, meaning responses generated by outer middleware (like the CORS preflight response, or a 429 from the rate limiter) would bypass it and ship without security headers.

## Consequences

- `/docs` and `/redoc` are a deliberate CSP gap — anyone hardening this further should know it's intentional, not an oversight, and that the mitigation is "disable or protect `/docs` in production" (already called out in the deployment checklist) rather than "add CSP there too."
- Any future middleware added to `main.py` needs to be aware of this ordering constraint if it wants its own responses (e.g. a custom error handler middleware) to also carry the security headers — it must be registered *before* `install_security_headers(app)`, not after.
